# Changelog

What changed in each release. Each GitHub release names its commit.

## 0.6.0

Breaking:

1. Exit codes are now 0 done, 1 a finding or not done, 2 bad call, and 5
   held for a person's yes. Exits 3 (dependency) and 4 (Git or file access)
   are gone; both are now 1. A cancelled setup and Ctrl-C exit 1 (were 2).
   `setup` with no terminal, no `--yes`, and an identity that is not the
   checkout's record exits 5 (was 2). A setup that a retry may clear exits 1
   (`setup-blocked`), and so does a setup whose result failed its check
   (`setup-failed`). Hooks are unaffected: pre-commit tests for non-zero
   only.
2. With `--format json`, every handled error prints one
   `{"error":{"code","message","next"}}` object on stdout, and nothing else
   there. `next` lists commands that start with an absolute path. Text mode
   keeps its `error:` and `fix:` lines on stderr. See
   [Output](ARCHITECTURE.md#output).
3. `--version` followed by anything but `--format` exits 2.
4. The pre-push hook runs `doctor` and the pushed history only. The working
   tree and the index are checked at commit time and by `check`, so a local
   draft no longer blocks a push, and the push no longer runs the other policy
   rules on a commit made with `--no-verify`
   ([Known gaps](ARCHITECTURE.md#threats-and-known-gaps) item 12).
5. A history or push scan that cannot read the whole history, as in a
   blobless clone, exits 1 with `dependency-missing` (it passed before).

Added:

1. Each verb's `--help` ends with `Writes:`, `Before:`, `Effects:`, and
   `Exit codes:` lines. A `help` verb prints the help as text, as one JSON
   object (`help --format json`, with a `verbs` list), or as Markdown.
2. `--version --format json` and `version --format json` print `version`,
   `revision`, and `modified`.
3. `skills/first-commit/SKILL.md` is the agent skill, generated by
   `first-commit help --format markdown`. The README shows how to write it
   for Claude Code and Codex. The hand-written `.agents/skills` skill is gone.
4. `setup --hooks installed` writes `repo: local` hooks that run the
   `first-commit` on PATH, with no pinned commit. Setup and `doctor` refuse a
   `first-commit` that is missing from PATH or sits inside the repository,
   and setup runs it once to confirm it prints a version. The default stays
   `--hooks pinned`. See [Hook file rules](ARCHITECTURE.md#hook-file-rules).
5. `check --new-only` checks only the commits no configured remote holds;
   with no remote, the whole history.
6. The user-level private-values list does not apply in the repository that
   tracks it, because that repository holds its words by design. Its values
   still mask output there. See [Private values](ARCHITECTURE.md#private-values).
7. A missing `.repo-policy.json` has its own error code, `policy-missing`.
8. An unknown flag lists every flag the verb accepts.
9. The pre-push hook stops a pushed commit with no signature, such as one
   made with `git commit --no-gpg-sign`, as `git.unsigned-commit`. It checks
   only that a signature is there, and its fix line re-signs the unpushed
   commits. A commit older than the clone's setup is skipped, so adopting
   first-commit needs no rewrite of older history. `check` reports the same
   unsigned commits before the push.
10. The pre-push hook runs the privacy rules on each file version the pushed
    commits add or change, so a private value committed with `--no-verify`
    and deleted in a later commit still blocks the push. A finding names the
    path, the line, and the commit, never the value, and its fix line says
    how to remove it from that commit.
11. The commit hook also checks the working copy of each staged Git LFS file,
    whose index copy holds only a pointer. A missing working copy, or one that
    is not a regular file, is a `files.filtered-unreadable` finding; one over
    10 MiB warns. Other clean filters, such as git-crypt, keep the index copy.

Changed:

1. Security: `bin/first-commit` no longer runs a `first_commit/cli.py` from the
   current folder, so a repository cannot replace a checkout's launcher. A pip
   install was never affected.
2. The README installs the command into `~/.local/bin` and runs
   `first-commit` from PATH; the `FIRST_COMMIT` shell variable is gone. It
   names what install writes, its network use, and the state folder
   `~/.config/first-commit` with its `XDG_CONFIG_HOME` override.
3. The README no longer says the hooks stop an unsigned commit, or that the
   push checks pushed file contents for private values.
   [Known gaps](ARCHITECTURE.md#threats-and-known-gaps) names both. The
   README covers clones and upgrades with `--hooks installed`.
4. `scripts/release` prints the release steps in order: push the branch, wait
   for a green CI run on that commit on Linux and macOS, then push the tag.
5. Every Git process first-commit or Gitleaks starts gets fixed display
   settings, and the pathspec variables are removed, so a user setting such
   as `color.ui = always` no longer hides a secret from the scan.
6. A history or push secret finding names its commit, and its fix line says
   how to remove it from that commit.
7. A `bin/first-commit` hook entry counts as first-commit's hook only in
   first-commit's own checkout. A PATH folder inside the repository is refused
   even when it links outside.
8. Ignored env-shaped files no longer count toward the 10,000-path limit.
   Policy errors end with a fix line that lists the accepted fields. A bad
   message header also reports missing sections. In a linked worktree, the
   setup-naming fix lines point to the main worktree.

## 0.5.0

1. A user-level private-values list applies to every project:
   `~/.config/first-commit/private-values.txt`, or
   `$XDG_CONFIG_HOME/first-commit/private-values.txt` when that is an absolute
   path. It may be a link to a regular file. When its mode is wider than 600,
   first-commit removes group and other access if you own it (a 644 list
   becomes 600, a 744 list becomes 700), and otherwise warns; the check goes
   on either way. The project list keeps its rules. See
   [Private values](ARCHITECTURE.md#private-values).
2. A linked worktree applies the main worktree's project list as well as its
   own. Values only add.
3. `public_github_owner_urls` also allows a private value that is part of the
   owner name, such as `<value>-labs` in `https://github.com/<value>-labs/tool`.
   The whole owner name must be a name GitHub allows: 1 to 39 letters, digits,
   or hyphens. A value with a dot, a space, a slash, or a non-ASCII letter is
   never exempt.
4. `public_github_owner_urls` no longer exempts a value on the line after
   `https://github.com/`; the address and the owner must be on one line.
5. A relative `XDG_CONFIG_HOME` now counts as unset, as the XDG rules say. The
   user-level list and the machine identity file then live under
   `~/.config/first-commit/`.
6. Setup says when the user-level list also applies.
